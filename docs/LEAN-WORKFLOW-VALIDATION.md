# 轻量流程开发验证记录

日期：2026-09-07。基于公开 v1.0.1（`ee7f720`）的本地开发候选，尚未发布。

本次验证说明新流程可以实际出片和局部重做；不证明所有题材、长片或
同输入成片的审美质量已经优于旧版。

## 改动与验证范围

- 新项目使用一个创作负责人、一份 `broll-plan.json` 和每镜独立 HTML。
  长片可按连续章节分工；普通任务不再固定经过五个制作角色和两轮样片门禁。
- 原始 SRT/design 保留。程序检查时间覆盖、实际输出、镜头依赖与复用。
- 真实主体优先采用可识别的素材。SVG 保留图标、真实数据图、遮罩和关系表达用途。
- 原有 Recipe/runtime-plan v1–v4、Remotion/hybrid 和明确要求的版本比较走兼容入口。
  本次不修改旧项目状态，也不将旧项目自动迁移到新计划。

## 真实媒体验证

macOS，本地固定 HyperFrames 0.7.104、FFmpeg。输入为 24 秒、4 条各 6 秒的
合成 SRT，依次讲相机实物、前后比较、清楚的信息、简洁结论。预先准备一张
合法相机照片、本地字体和 GSAP。独立创作 Agent 根据原始输入与新 Skill 制作
四镜头，没有被提供目标 HTML。数字明确标注为演示数据。

首次源码写入到草稿复查约 5 分 08 秒；该区间包含创作、报错修正和两次整段
草稿输出，不包含预先寻找素材、环境准备或本次工程改造。

最终渲染器版本的实际调用结果：

| 操作 | 重渲镜头 | 复用镜头 | 耗时 |
| --- | ---: | ---: | ---: |
| 1080p/30fps 正式输出，含检查图与完整预览 | 4 | 0 | 25.348 秒 |
| 不改任何内容，再运行一次 | 0 | 4 | 0.174 秒 |
| 只改变 S02 的强调色，再输出 | 1 | 3 | 7.811 秒 |
| 960×540/15fps 草稿，含检查图与完整预览 | 4 | 0 | 17.322 秒 |

S02 修改在独立测试副本内完成：只有 S02 MP4 的 SHA-256 改变，S01/S03/S04
保持完全一致，完整预览重新组装。草稿和正式输出各 24.000 秒，H.264、无音轨，
经过完整解码检查。已检查四镜头六帧图和整段预览抽帧，并在浏览器确认高清
预览正常播放到末段；这不等于用户已经认可其审美。

前向测试发现并修正的实际问题：

- 固定 HyperFrames 版本需要显式初始化 `window.__timelines`、HTML 内的
  `@font-face`，以及相对项目根目录的素材路径；新版通用示例不能直接照搬。
- S02/S03 首帧过空，已使照片/核心信息在首帧可见。
- 渲染失败不再因 `--quiet` 丢失关键报错，返回具体失败信息供原作者修正。
- 每镜输出按全局帧边界分配，避免毫秒时间逐镜取整积累误差。
  自动化回归使用 20 段 × 101ms：30fps 下总计 61 帧，而非独立向上取整的 80 帧。

## Token 实验：只测计划首轮，不能作为等质量成片比较

同一份 24 秒 SRT/design，Codex CLI 0.153.4、`gpt-5.4-mini`、medium reasoning。
两个隔离工作目录分别读取公开 v1.0.1 Director 契约与新的轻量计划契约。
禁止出片、搜素材和委派；旧版按要求写 Director 交接，新版只写一个计划。
两个首轮任务并行执行。日志放在工作目录之外，避免模型误读自己的日志。

| 宿主实际报告 | 旧版 Director 首轮 | 轻量计划首轮 |
| --- | ---: | ---: |
| 用时 | 219.954 秒 | 60.049 秒 |
| 输入 Token（包含缓存） | 172,711 | 98,730 |
| 其中缓存输入 | 142,080 | 78,592 |
| 非缓存输入 | 30,631 | 20,138 |
| 输出 Token | 14,371 | 3,043 |
| 其中推理 Token（已包含于输出） | 7,990 | 1,232 |

轻量计划通过原始 SRT 与计划校验。旧版首轮未通过：`truth.sourceCues` 写成了
整数，旧校验要求字符串。另一次修复调用在 300 秒超时前仍未形成可验收交接，
且修复过程越过了限定读取范围，故排除其结果；没有完整宿主用量，不能把它
记成零 Token，也不能纳入有效比较。更早一轮存在日志污染，整体排除。

这组首轮数字支持“减少交接文件和重复推理值得继续验证”，不能支持“等质量
成片节省某个百分比”。缓存 Token 不等同于非缓存费用；未测金额、整片 Token、
重复实验方差或 Claude Code 同输入结果。

## 当前限制与复现入口

- 这是小型技术样片，题材单一、素材已备；尚无新版完整长片与旧版成片盲测。
- 共享素材、原始设计或共享代码改变时，当前实现保守地使所有镜头失效。
  只改独立镜头源码时局部重渲；不是精确到每张图片使用者的完整依赖分析。
- 1080p 源码的草稿仍先按原始尺寸捕获，再降采样；固定运行时没有任意
  sub-1080p 捕获档位。自定义正式尺寸必须与 HTML 原生尺寸相符。
- 新计划接受按时间排列、不重叠的普通 SRT；重叠字幕需先明确应如何解释，
  程序不会悄悄修改原始字幕。
- 新路径先覆盖 HyperFrames。已有后端和审批逻辑的回归测试保留；未做新版本发布、
  跨平台重新安装或全局 Skill 切换。

制作与局部修改入口见 [轻量制作命令](../erduo-broll-loop-engineering/references/lean-production.md)。
新增计划/渲染回归覆盖真实 CLI 入口、短片、时间覆盖、缓存失效、部分预览、
失败续跑、解码失败和累计帧边界。运行 `npm test` 检查完整新旧契约。
本次完整测试 **228/228 通过、无跳过**；其中新增计划/渲染测试 24 项。
14 个项目 Skill 通过官方 `quick_validate.py`，`git diff --check` 通过。
