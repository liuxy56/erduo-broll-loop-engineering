# Erduo B-roll Loop Engineering

Create useful pictures for the spoken meaning with the fewest necessary handoffs.
The same creative owner understands, designs, builds, views, and repairs a
continuous passage. Scripts own timing checks, rendering, reuse, and assembly.

## Choose once

- An existing `broll-plan.json` uses the lean workflow below.
- An existing Recipe/runtime-plan v1–v4 project, explicit Remotion/hybrid, or an
  explicit five-shot version comparison uses [legacy production](references/legacy-production.md).
  Preserve its inputs and approvals; do not silently migrate it.
- New work defaults to lean HyperFrames. Load only
  [production commands](references/lean-production.md) and
  [visual direction](references/lean-visual-direction.md).

## Own the creative work

Read the complete original SRT and original design. Preserve spoken facts,
semantic timing, supplied media and the user's output choices. If no design is
supplied, make a short direction from the request; do not start an interview.
Keep original inputs in a fresh project folder. Never alter user originals.

Normally create directly in this context. For a long or genuinely complex film,
delegate continuous chapters to a small number of creators with disjoint shot
files. Give each the originals, shared style/media, its shots and adjacent seams;
never the full conversation or every legacy Skill. Keep revisions with its owner.
Use a separate material researcher only when real selection work warrants it.
There is no mandatory Director, Assets, Lead, Reviewer or per-shot agent chain.

Write one compact `broll-plan.json`, then editable `compositions/<id>.html` files.
Use recognisable material and clear information; abstract hand-drawn SVG is not
a substitute for the subject. Share assets and useful primitives, not identical
whole-shot layouts. Read the installed HyperFrames core contract once if needed.

## Make, view, revise

Validate the plan, render draft shots, view their sheets and the moving preview,
and fix visible defects. Uncertain new visual treatments may need an early
sample; choose it for the actual problem. There is no fixed sample count,
material quota, five-shot competition, or extra approval form in ordinary work.
Respect any review stop the user requested. Render final when authorised by the
request or approved preview; an autonomous test includes its test renders.

Run the standard command again after edits; unchanged shots are reused. Return
actual failed-shot details to its owner. Do not make the model write hashes,
validation reports, duplicate plans, or decorative proof artifacts.

Deliver the ordered shot files, editable project, preview, output facts and real
limitations. Report measured time/operations; report tokens only from actual
host usage. A passing decode or generated sheet is not a viewing conclusion.
Follow [safe execution](references/safe-execution.md) for external commands.
